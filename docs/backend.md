# Контракт будущего бэкенда

Фронтенд готов к подключению собственного сервера через `LeadsRepository`. Реальная Instagram-интеграция пока не реализована. Подключение не требует переписывать компоненты: переключается `VITE_DATA_MODE=api`.

## HTTP

| Метод | Маршрут | Ответ |
| --- | --- | --- |
| GET | `/api/leads` | `200`, JSON-массив `Lead[]`, в том числе пустой `[]` |
| PUT | `/api/leads/:id` | `200` или `201`, сохранённый `Lead` |
| DELETE | `/api/leads/:id` | `204` без тела |

`PUT` создаёт или обновляет контакт по переданному UUID. Фронтенд генерирует UUID; демонстрационные контакты используют ID вида `demo-0`. Возвращаемое тело `PUT` является источником истины для интерфейса. Ошибки: `401` — требуется авторизация, `403` — нет доступа, `409` — конфликт ника, остальные `4xx/5xx` — ошибка запроса. Таймаут клиента — 15 секунд. Схемы Zod проверяют ответы API; некорректные данные не попадают в состояние приложения.

Запросы отправляются с `credentials: include`. Рекомендуемый вариант — same-origin сервер и сессионные HttpOnly cookies. Проверка прав на каждую запись, валидация данных, защита от CSRF и уникальность ника в пространстве пользователя выполняются на сервере. `VITE_API_BASE_URL` — публичный адрес API, не секрет.

Для текущего интерфейса API возвращает всю базу. При росте базы добавьте серверную пагинацию и фильтрацию через расширение интерфейса репозитория. Групповой перевод сейчас выполняет последовательные `PUT`: успешные изменения сохраняются, при первом сбое операция останавливается и показывает ошибку. Для больших групп нужен серверный пакетный endpoint с определённой транзакционной семантикой.

## Модель

Типы и runtime-схемы находятся в `src/lib/domain.ts`.

```ts
type StageId = 'new' | 'dialogue' | 'booked' | 'called' | 'payment' | 'won' | 'lost';

type Lead = {
  id: string;
  name: string;             // 1–60 символов
  handle: string;           // нормализованный ник без @, lowercase
  stage: StageId;
  amount: number;           // 0–100 000 000, рубли
  source: 'manual' | 'manychat' | 'instagram';
  keyword: string;
  product: string;
  note: string;
  nextAction: string;
  due: string;             // YYYY-MM-DD или ''
  priority: 'normal' | 'hot';
  lostReason: string;
  color: number;           // индекс цвета аватара
  created: string;         // ISO UTC timestamp
  updated: string;         // ISO UTC timestamp
  history: {
    at: string;
    kind: 'created' | 'stage' | 'note' | 'incoming' | 'task';
    text: string;
    to?: StageId;
  }[];
};
```

## Правила

- Один нормализованный `handle` на контакт в рабочем пространстве. Для реальной Instagram-интеграции добавьте стабильный provider user ID на сервере: ник может меняться.
- При `won` или `lost` очищаются `nextAction` и `due`.
- При отказе требуется `lostReason`.
- Для заполненной даты требуется текст следующего действия.
- История достигнутых этапов используется в аналитике. Не удаляйте её при обновлении контакта.
- В продакшене сервер должен сам проверять переходы и формировать авторитетную историю, а не доверять истории из тела клиентского запроса.
- Даты задач — календарные даты устройства пользователя; временные метки событий — ISO UTC. Часовой пояс аккаунта стоит явно хранить на сервере, если появятся напоминания и совместная работа.
- При совместном редактировании добавьте версию записи / ETag и `If-Match`. В текущем прототипе применяется последнее сохранение.

## Где подключать Instagram и ManyChat

На сервере понадобятся обработчики OAuth, хранение токенов, верификация webhook и идемпотентная обработка входящих событий. Сервер определяет рабочее пространство, находит контакт по provider ID, создаёт или обновляет его и записывает событие в историю. Повторные входящие не должны сбрасывать текущий этап.

Тестовое входящее во фронтенде демонстрирует именно эту логику; это не подключение к сервису. В API-режиме симуляция отключена. Кнопку реального подключения и статус интеграции можно добавить после появления соответствующих серверных endpoint. Для отображения новых входящих можно добавить SSE, WebSocket или периодическую перезагрузку через репозиторий.

Секреты, app secret и access/refresh tokens не размещаются в браузере, `localStorage` или переменных `VITE_*`. Ограничения и права конкретной версии Instagram API проверяются при реализации серверной интеграции.
