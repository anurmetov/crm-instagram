# Поток

Адаптивная CRM для Instagram на **React + TypeScript + Vite**, собранная по исходному макету `index (1).html`. Исходный HTML сохранён без изменений.

## Запуск

Нужен Node.js 22.12+.

```sh
npm install
npm run dev
```

Откройте **http://localhost:5173**. Для проверки с телефона подключите компьютер и телефон к одной Wi-Fi сети и откройте `http://<локальный-IP-компьютера>:5173`. Vite выводит адрес `Network` при запуске. Windows может запросить доступ к частной сети.

```sh
npm run build       # TypeScript + production-сборка в dist/
npm run preview     # просмотр production-сборки
npm test            # тесты правил CRM, CSV и хранилищ
npm run test:e2e    # сценарии в браузере: desktop + мобильная эмуляция
```

Браузерные тесты по умолчанию используют установленный Google Chrome. Если Chrome отсутствует, установите Chromium командой `npx playwright install chromium` и удалите `channel: 'chrome'` из `playwright.config.ts`.

## Что работает

- Воронка из семи этапов с перетаскиванием карточек на компьютере.
- На телефоне — нижняя навигация, закреплённые поиск и вкладки этапов, вертикальные карточки, быстрый переход к следующему этапу и кнопка добавления под большим пальцем при прокрутке.
- Контакты в карточках, поиск, сортировка, фильтры и CSV найденных контактов.
- Создание и редактирование контактов, защита от дублей Instagram-ников, заметки, суммы, продукты, приоритет и история.
- Аналитика по фактическим данным: выручка, потенциал, конверсия, источники и история достигнутых этапов.
- CSV с UTF-8 BOM для русских имён, разделителем `;` и защитой от формул в ячейках.
- Формы в мобильной панели с закреплённой кнопкой сохранения, предупреждением о несохранённых изменениях и поддержкой клавиатуры.
- Иконки и manifest для добавления ярлыка на главный экран через меню мобильного браузера. Полного офлайн-кэширования приложения пока нет.

В деморежиме база сохраняется **только в текущем браузере на текущем устройстве и origin**. `localhost` и адрес компьютера в Wi-Fi — разные origin. Между вкладками одного origin данные обновляются через событие `storage`. Исходные данные из ключа `potok-crm-demo-v1` автоматически читаются; после изменения сохраняются в `potok-crm-v2`. Повреждённые данные не перезаписываются демоданными.

## Структура

```text
src/
  App.tsx                 оболочка, навигация, уведомления
  components/             воронка, карточки, форма, аналитика
  hooks/useCrm.ts          загрузка и обновление состояния
  lib/domain.ts           типы, схемы данных, фильтры и правила CRM
  lib/export.ts           экспорт CSV
  data/seed.ts            20 контактов исходного макета
  services/leads.ts       интерфейс хранилища + localStorage / HTTP
  styles.css              desktop, tablet, mobile, safe-area
public/                   иконки и web manifest
tests/                    модульные и браузерные сценарии
docs/backend.md           контракт для будущего сервера
```

## Подключение бэкенда

Скопируйте `.env.example` в `.env.local` и переключите режим:

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=/api
API_PROXY_TARGET=http://localhost:3000
```

Перезапустите Vite. Демо-хранилище заменится на `ApiLeadsRepository`; серверные ошибки и ошибки авторизации будут показаны пользователю. При недоступном API приложение не подменяет серверные данные демоданными.

Описание маршрутов и модели: [docs/backend.md](docs/backend.md). Сервер, база данных, авторизация и реальное подключение Instagram/ManyChat в этот этап не входят. OAuth и секреты Instagram должны находиться на сервере; переменные `VITE_*` публично доступны в браузере.

## Публикация

Содержимое `dist/` можно разместить на статическом хостинге. Приложение использует hash-навигацию: дополнительные server rewrites для разделов не нужны. При API-режиме настройте `/api` на ваш сервер: Vite proxy работает только во время разработки. Для установки на главный экран с мобильных устройств используйте HTTPS; исключение для локальной разработки — `localhost`.
